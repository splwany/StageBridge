# 架构与行为约束

台前随屏（StageByScreen）不依赖第三方库。UI 与监听流程在主线程协调，只有短时系统命令在后台执行。

## 模块

- `Sources/Core`：连接变化策略、睡眠/唤醒状态和错误类型；无 UI 依赖。
- `Sources/App/Monitor.swift`：协调用户设置、显示器事件、定时检查、睡眠通知和异步控制结果。
- `Sources/App/SettingsView.swift`、`StageByScreenApp.swift`：原生设置页与菜单栏生命周期。
- `Sources/Services/DisplayEvents.swift`：拥有 CoreGraphics 回调注册，停止后不再转发事件。
- `DisplayReader.swift`：读取在线显示器，拒绝空列表和读取期间容量变化。
- `MonitorScheduler.swift`：主线程防抖与公共 RunLoop 模式下的备用定时器。
- `StageManagerControl.swift`：检查已有偏好、写入并回读，必要时重载 Dock；系统接口为实验性后端。
- `ProcessRunner.swift`：异步命令、5 秒超时、取消、合并诊断。输出采用临时文件避免管道死锁，最多返回 16 KB，完成后清理。
- `EventLogger.swift`：本地轮换日志。

## 必须保持的行为

只有“至少一个外接屏”的布尔状态发生变化时，才产生一次控制请求。同一状态下的轮询、事件和手动操作不会重复执行控制。启动、恢复、唤醒只建立基准。

显示器防抖为 2 秒，唤醒稳定等待为 3 秒。两类任务独立；暂停与重新启用不能跳过唤醒等待。调整备用间隔只替换定时器，不取消显示器事件。

连接基准在执行前更新，失败不自动重试。这是为避免延迟重试覆盖用户的手动操作。新连接变化、暂停和睡眠会取消旧命令，并使旧异步结果失效。已经完成的系统偏好写入无法通过取消撤销。

偏好已经是目标值时不重载 Dock。未知偏好、同步失败或回读不一致时不执行 Dock 命令。成功只说明偏好与命令处理完成，不能证明所有 macOS 版本上的可见效果。

## 测试边界

`CoreChecks` 验证策略、睡眠状态、真实无害子进程的超时与取消。`MonitorChecks` 注入显示器读取、事件源、计时器、通知中心与控制函数，验证真实协调代码；控制后端使用内存偏好与模拟 Dock 命令。

测试不会更改台前调度，不会停止旧 LaunchAgent，不会改动用户正式偏好。实际插拔、合盖、登录和跨系统兼容性仍需对应硬件验收。
